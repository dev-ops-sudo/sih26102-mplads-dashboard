# SIH26102 MPLADS Intelligence & Risk Monitoring

This project contains the original React dashboard plus a standalone backend starter. The React frontend intentionally continues to use `src/data/mockData.ts`; it is **not connected to the API**, so you can integrate it according to your final requirements.

## Backend stack

- FastAPI, Pydantic, SQLAlchemy, Alembic, and generated OpenAPI documentation.
- PostgreSQL with PostGIS geographic indexing and pgvector-ready source-document storage.
- Redis and Celery for scheduled risk and duplicate-detection jobs.
- S3-compatible evidence storage through MinIO, with local-file fallback.
- Keycloak/OIDC JWT validation and national/state/district roles.
- PostgreSQL row-level security plus matching application-level scope checks.
- Optional OpenAI Responses API investigation adapter with a no-key evidence-grounded fallback.
- Seed data, migrations, audit events, ingestion contracts, and API tests.

## Start the complete backend

Docker Desktop must be running.

```powershell
Copy-Item .env.example .env
npm run stack:up
```

Backend services:

- API: `http://localhost:8000`
- API documentation: `http://localhost:8000/docs`
- Keycloak: `http://localhost:8080`
- MinIO console: `http://localhost:9001`
- PostgreSQL: `localhost:5432`
- Redis: `localhost:6379`

Authentication is disabled by default, so the API can be tested immediately. Stop everything with:

```powershell
npm run stack:down
```

## Lightweight backend development

This mode uses SQLite and local evidence storage. PostgreSQL, Redis, MinIO, and Keycloak are not required.

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -e ".\backend[test]"
npm run dev:api
```

## Run the existing frontend separately

```powershell
npm install
npm run dev
```

The frontend remains mock-data-driven. Its stable TypeScript contracts are in `src/types.ts`, and its replaceable demonstration data is in `src/data/mockData.ts`.

## Backend structure

```text
backend/app/
  api/                 REST endpoints
  services/            risk, duplicate, storage, investigation, audit
  workers/             Celery jobs and scheduling
  auth.py              OIDC/JWT roles and database scope
  models.py            persistent domain model
  schemas.py           validated request and response contracts
  seed.py              replaceable demonstration records
```

Core tables cover projects, agencies, milestones, transactions, inspections, evidence media, anomalies, risk assessments, weighted contributions, predictions, duplicate relationships, alerts, investigation history, source documents, ingestion runs, and append-only audit events.

The project list accepts repeated `states`, `districts`, `constituencies`, `types`, `statuses`, and `risks` parameters, plus `search` and `limit`.

All responses use camel-case names matching the current frontend types. For example, database fields `risk_score` and `budget_cr` are returned as `riskScore` and `budgetCr`.

## Risk and investigation design

Risk scores are deterministic and auditable. The engine records five weighted contributions: cost variance, schedule slippage, evidence confidence, duplicate similarity, and agency history. Every assessment stores the rule version, evidence snapshot, generation time, and individual explanations.

The investigation assistant receives only read-only evidence. Without an API key it returns deterministic guidance. With `OPENAI_API_KEY` configured, it uses the optional provider adapter; the risk score itself is never generated by the language model.

## Configuration

Copy `.env.example` to `.env`. Replace every password before using a shared environment.

- `MPLADS_DATABASE_URL`: PostgreSQL or SQLite connection.
- `MPLADS_AUTH_ENABLED`: enables backend JWT validation.
- `MPLADS_STORAGE_BACKEND`: `local` or `s3`.
- `MPLADS_REDIS_URL`: Celery broker and result backend.
- `MPLADS_CELERY_ENABLED`: queues jobs in Redis; leave false for in-process development fallback.
- `OPENAI_API_KEY`: optional investigation provider.
- `OPENAI_MODEL`: optional provider model override.

The imported development Keycloak user is `demo.admin`. Its temporary password is `demo-only-change-me`, and Keycloak requires a new password at first login.
